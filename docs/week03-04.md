## 3. 可复现问题及最小修改

原现象：从已保存的 I 仓库 `29d7d700…` 中仅提取 `NavigationClient._result_cb/_await_result` 两个已审查的无网络方法，输入人工 `old-goal / SUCCEEDED`。方法返回 `(True, 'old goal reached')`，没有检验当前目标。没有导入 rospy、启动节点或运行整个巡检程序。

新增 [move_base_adapter.py](../examples/move_base_adapter.py) 是**无通信的消息边界模块**，不修改参考仓库：

- 使用实际 goal_id 精确匹配；发布/跟踪状态本身不能产生 REACHED。每次执行使用唯一 goal_id，新尝试创建新实例。
- 仅当前目标的 SUCCEEDED 结果产生 REACHED；ABORTED/REJECTED/PREEMPTED/RECALLED 映射为 FAILED，并保留原因。
- 单调时钟计算超时，避免依赖可能暂停的 ROS 仿真时间。超时后即使迟到成功也保留 TIMEOUT。
- 取消仅产生指定 goal_id 的请求意图；取消确认与 Action 终态单独记录。LOST 不表示服务器确认结束，任何状态均不能证明机器人已停止。
- 明确检查目标坐标系，不隐式变换；支持位姿来源标签。传输层须按时间顺序串行交付事件，本模块不承担 ROS 回调线程、服务器可用性或物理安全控制。

| 同一人工输入 | 参考方法 | 新模块 |
| --- | --- | --- |
| 等待 current-goal，收到 old-goal 成功 | 返回 True（FAIL：不满足关联要求） | 保持 RUNNING（PASS） |
| 随后收到 current-goal 成功 | 本轮不重复整套参考流程 | REACHED（PASS，仅接口） |
| 期限已到才收到成功 | 不作为本轮参考方法对比项 | TIMEOUT 保持不变（PASS） |

这修复的是本项目适配边界的语义，参考系统缺陷尚未部署修复。实际发送、取消及 ActionClient 接入必须等仿真环境和控制隔离确认后完成；`pending_cancel_goal_id` 不会自动执行任何动作。
